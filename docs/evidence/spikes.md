# Spikes: things verified against the live workspace

| Date | Item | Finding |
|---|---|---|
| 2026-10-15 | ai_query batch inference with Claude | `databricks-claude-sonnet-5-5` and `-sonnet-5` are rejected ("not supported for batch inference"). `-sonnet-4-6`, `-sonnet-4-5` and `-haiku-4-5` work. The DQ digest pins `-sonnet-4-6`. Interactive calls through the gateway still use Sonnet 5.5. |
| 2026-10-15 | ai_query responseFormat | The DDL struct form is rejected for Claude endpoints; the JSON-schema form works. |
| 2026-10-15 | Serverless Python file tasks | `__file__` is not defined; jobs pass `--src-dir`. `.cache()` is not supported on serverless. |
| 2026-10-15 | RESTORE on streaming tables | Not supported (docs). Pipeline tables recover by refresh from bronze or reprocess. |
| 2026-10-15 | System tables | All readable here, including `system.ai_gateway.usage`. Observed lag: audit, lineage and query history 7-10 min; billing about 1h. |
| 2026-10-15 | Governed tags | Account tag-policy limit reached (3072), so no new governed tags. ABAC keys on Data Classification system tags (`class.*`, including `class.sg_nric`); the row filter reuses `row_scope=country`. |
| 2026-10-15 | Groups | The workspace SCIM API creates workspace-local groups (not usable in UC grants); account groups are created via the workspace-proxied account SCIM API. |
| 2026-10-15 | Catalogs on Default Storage | UI only; the API returns "Please use the UI to create a catalog with Default Storage". |
| 2026-10-15 | Auto Loader drift | When the drift file is present at the first schema inference, the new column is inferred instead of rescued; land the baseline first. |
| 2026-10-15 | Serverless task retries | Serverless auto-optimization retries a failed task once (about 60 s later) even with no retry policy, so a deliberate check failure ran twice and wrote its breach twice. `max_retries: 0` does not help: the bundle drops the zero value. `disable_auto_optimization: true` on the task stops it. Source: https://docs.databricks.com/aws/en/jobs/run-serverless-jobs (read 2026-10-15). |
| 2026-10-15 | Job health rule name (⚠ T06) | `RUN_DURATION_SECONDS` with `GREATER_THAN` deploys and is accepted by the Jobs API; the notification key is `on_duration_warning_threshold_exceeded`. |
| 2026-10-15 | Run result with `run_if: AT_LEAST_ONE_FAILED` | When checks fail and the escalate task succeeds, the run ends `SUCCESS_WITH_FAILURES`; job-level `on_failure` email does not cover it, so the check tasks carry task-level `on_failure`. A parent `run_job_task` counts the child as succeeded. |
| 2026-10-15 | DESCRIBE HISTORY on streaming tables | Works, and is immediate: a DML write by a job shows `jobName`, `jobId`, `jobRunId`, the predicate and `numUpdatedRows`. Time travel reads (`VERSION AS OF`) work too. Its `triggerType` says `manual` for table-triggered runs; the Jobs API run says `TABLE`. A selective full refresh shows as `DLT REFRESH`. |
| 2026-10-15 | Selective full refresh | `databricks bundle run <pipeline> --full-refresh <silver table> --refresh <gold MVs>` recomputes one streaming table from bronze in about 1 to 1.5 min on tiny data; column tags and ABAC policies stay in place. |
| 2026-10-15 | Lineage for job writes | `system.access.table_lineage` records serverless job reads and writes of ordinary tables as `entity_type = JOB` with `entity_id` (job ID) and `entity_run_id` (job run ID), and pipeline writes as `PIPELINE` with the update ID. DML into a pipeline streaming table from a job (an `UPDATE`, a `MERGE`, and the reprocess job's `MERGE`; dev and prod) left no lineage row, while the same job's read of the streaming table and its insert into an ordinary table were recorded. `DESCRIBE HISTORY` records the write. Observed lag 7 to 30 min. Rows with a null entity type are ad hoc SQL. |
| 2026-10-15 | Pipeline event log as a table | `event_log: {catalog, schema, name}` on an existing pipeline takes effect on its next update and publishes `obs.pipeline_event_log`; expectation metrics are in `details:flow_progress.data_quality.expectations`. |
| 2026-10-15 | Bundle presets | Top-level `presets.tags` adds a `target` tag to every job and pipeline (development mode keeps its `dev` tag). `system.lakeflow.jobs` reflects new tags with a lag. |
| 2026-10-15 | System tables as the CI principal | `meridian-ci` can read `system.lakeflow`, `system.query`, `system.access` here, so the prod views and the lineage changelog run as the job identity. |
| 2026-10-15 | Unity Catalog secrets status | GA since 2026-08-03 ("Secrets in Unity Catalog is GA", https://docs.databricks.com/aws/en/release-notes/product/2026/august, read 2026-10-15); our PREVIEW labels were stale and are corrected. Native read: `dbutils.secrets.get(catalog=, schema=, key=)` on serverless environment 4+. Audit: `system.access.audit`, `service_name = 'unityCatalog'`, `action_name LIKE '%Secret%'` (https://docs.databricks.com/aws/en/security/secrets/unity-catalog-secrets). |
| 2026-10-15 | Secret grants | `READ SECRET` cannot be granted on a schema here ("not applicable ... privilege version of the metastore [1.0]"), and `GRANT ... ON SECRET` through the SQL warehouse fails with `UC_SECRETS_NOT_ENABLED`; the UC permissions REST API (`PATCH /api/2.1/unity-catalog/permissions/secret/<name>`) works. `apply_governance.py` grants per secret through it. |
| 2026-10-15 | Deleting a pipeline | Since 2026-09-25, deleting a Unity Catalog pipeline (default publishing mode) keeps its streaming tables and materialized views; they cannot be updated until moved into an active pipeline. `cascade=true` on the delete API removes them (https://docs.databricks.com/aws/en/release-notes/product/2026/september). The API reference still describes the old cascading default. |
| 2026-10-15 | Bundle `presets.name_prefix` | `ci_` becomes `ci` on schema names (`cibronze`); a bracketed prefix like development mode's works: `"[staging] "` gives `[staging] meridian-dlc` and `staging_bronze`. Staging and prod share a workspace, and pipeline names must be unique there (409 `RESOURCE_CONFLICT`): ci uses a `"[ci] "` prefix; staging keeps prod's schema names in its own catalog and renames only its pipeline. |
| 2026-10-15 | Secret audit events | `system.access.audit`: `createSecret`, `getSecret`, `updateSecret` under `unityCatalog`, with `request_params.full_name`; a denied read (no USE SCHEMA) is logged as `getSecret` with status 500 and "Exception: null", while the client receives PermissionDenied. Lag about 30 min. |
| 2026-10-16 | `ai_parse_document` output | Format version 2.0: `document.elements[]` with `type` (`title`, `section_header`, `text`, `table` as HTML, `page_header`, `page_footer`, `page_number`), `content` and `bbox[].page_id`; per-file errors in `error_status`. Works from the SQL warehouse and serverless jobs. |
| 2026-10-16 | `read_files` in a view | A UC view over `read_files` works for `binaryFile`, `csv`, multi-line `json` and whole-file `text` on a volume; the view reads the files at query time as the caller (the job identity reads the volume). |
| 2026-10-16 | AI Search indexes in bundles | `vector_search_indexes` is a bundle resource with UC `grants`. Index creation needs the source table, so the indexes are target-scoped (dev, prod). Querying needs `USE SCHEMA` as well as `SELECT` on the index; without `USE SCHEMA` the error still says "do not have the SELECT privilege". The CI principal can start syncs of indexes the deployer owns. |
| 2026-10-16 | Workspace IP access list | The workspace blocks API calls from IPs outside its access list ("Source IP address ... is blocked by Databricks IP ACL"); a VPN drop on the laptop briefly blocked every call. Demo machine must be on an allowed network, or the venue IP added. |
| 2026-10-16 | File-arrival triggers and edits | "Only new files trigger runs. Overwriting an existing file with a file of the same name does not trigger a run" (https://docs.databricks.com/aws/en/jobs/file-arrival-triggers, read 2026-10-16); deletes do not trigger either. Observed: the freshness probe's edits and deletes started no kb_sync run. A 10-minute sweep job (run-job task on the queued kb_sync job) covers them. |
